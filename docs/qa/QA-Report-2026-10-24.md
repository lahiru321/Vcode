## 1. Executive summary

- **Every automated gate passes on the committed code:** lint, typecheck, 436 unit tests and 6 E2E smoke tests. The Prettier check fails only on two **uncommitted** WIP files (BUG-02).
- **I ran 85 exploratory checks against the built app** (77 in the first pass, 8 in triage), covering IPC validation, path traversal, option injection, XSS, CSP, secrets handling, terminal limits, concurrency, performance and basic accessibility.
- **Security hardening is strong.** Every attack I tried was blocked: path traversal, junction escape, git option injection, navigation to remote URLs, `file://`, `eval`, network requests, clipboard reads, Node access from the page, and `app://` traversal. Secrets did not appear in plain text in the database, logs, audit log or IPC responses.
- **One confirmed major defect (BUG-01).** **Remove project** deletes the project's records but does not stop its running shells or agents. They keep running with no UI to see or stop them, and they no longer count toward the "max terminals" limit.
- **Performance is good.** 200,000 lines of terminal output finished in about 10 s. The UI round-trip never went above 3 ms, and the whole app used about 650 MB.

## 4. Defects

### BUG-01: [Projects] Removing a project leaves its terminals and agents running invisibly

- **Severity:** Major
- **Priority:** P2
- **Environment:** `a2167b3` (0.1.2) and the WIP tree, built app, Windows 11, default shell PowerShell
- **Preconditions:** A project with at least one running terminal (shell or agent).
- **Steps to reproduce:**
  1. Add a project (any folder), select it and press **Ctrl+Shift+T** to open a shell.
  2. In the shell, start a long-running process. Example: `node -e "setInterval(()=>require('fs').writeFileSync('beat',String(Date.now())),500)"`
  3. In the sidebar, open **⋯ → Remove** for the project and confirm **Remove project**.
  4. Look at the `beat` file in the folder, or at Task Manager.
- **Expected:** One of these:
  - The app refuses, as it already does for workspaces (*"CONFLICT … while a terminal is running in it"*, `workspaces/service.ts:322`).
  - The dialog warns that N terminals are running, then stops them.
- **Actual:**
  - The dialog says only *"Its settings in Vcode are deleted. The folder and every file in it stay on disk."* It does not mention the running terminals.
  - After removal, the shell (`powershell.exe`) and its child keep running: the heartbeat was still advancing 7 s later.
  - No panel shows the processes, so there is no way to stop them from the UI.
  - Re-adding the same folder does not show them either (`terminals:list` → 0).
  - They no longer count toward **Settings → max terminals**. With `maxTerminals = 1`, a new terminal was allowed while the orphan was still running.
  - They end only when the app quits.
- **Reproducibility:** Always (2/2: once through IPC, once through the UI)
- **Evidence:** Triage run output:
  ```json
  "beforeRemove": "powershell.exe parent=25368",
  "afterRemove": { "shell": "powershell.exe parent=25368", "heartbeatStillAdvancing": true, "msSinceLastBeat": 576 },
  "visibleTerminalsInUI": 0, "readdedTerminals": 0, "afterAppExit": "GONE"
  ```
- **Impact:** With an **agent** terminal, a coding agent keeps editing files in the folder and spending API credit with no visible UI. The user has no way to see or stop it short of quitting Vcode or killing it in Task Manager.
- **Suspected root cause:**
  - The `projects:delete` handler (`apps/desktop/src/main/ipc/projects.ts:29`) calls `deleteProject()`, which only runs `DELETE FROM projects` (`projects/service.ts:119`).
  - The DB cascade (`projects → workspaces → terminal_sessions`) removes the session rows, but nothing tells the PTY host to kill those PTYs.
  - The running-terminal count is read from the DB, so the orphans drop out of the limit.
- **Suggested fix:** Match the workspace rule and refuse with CONFLICT while terminals run, with the dialog offering "Stop terminals and remove". Or stop every session in the project through the terminal service before the delete. Add an E2E test for this case.

### BUG-02: [Build] Prettier check fails on the uncommitted Markdown-viewer files

## 5. Questions for product / observations (not filed as bugs)

| ID | Observation | Question / recommendation |
|---|---|---|
| Q-01 | `C:\Windows\System32` (or any system folder) is accepted as a project root. Only whole-drive roots are refused. | Should system folders (`%SystemRoot%`, `%ProgramFiles%`) be refused or warned about? An agent in System32 can do a lot of damage. |
| Q-02 | An API key can be saved under env var `PATH` (or `PATHEXT`, `COMSPEC`, …). That replaces `PATH` in the agent's environment and breaks it. | Should well-known system variables be blocked for API keys? |
| Q-03 | `settings:set { selectedProjectId: <id of no project> }` is accepted and stored. | Probably harmless: the renderer falls back. Consider validating the id. |
| OBS-03 | An E2E-forced exit (`app.exit(0)`) logs `PTY host exited unexpectedly; restarting it` (level 50) during shutdown. | Low confidence: the test helper skips the normal quit path. Check whether a normal quit also logs this. If it does, it's log noise that could hide real crashes. |
| OBS-04 | Code review: pasted images are named with a millisecond timestamp (`ipc/clipboard.ts`). Two pastes in the same millisecond would overwrite each other. | Very unlikely. Add a random suffix if it's cheap. |
| OBS-05 | The renderer ships as one 2.94 MB JS chunk. | Fine for a local desktop app (cold start measured at about 0.8 s). Worth splitting if start-up slows. |

## 7. Key risks

1. **Orphaned agents (BUG-01).** This is the most user-visible risk. An AI agent keeps editing files and spending API credit after the user thinks they removed the project.
2. **Untested release path.** Installer, upgrade-in-place and real auto-update were not exercised here. Past sessions show auto-update has failed before (0.1.1). A manual upgrade test on a clean VM is the most valuable next step.
3. **Real agent integrations** (Claude / Gemini / Codex CLIs, status detection, notifications) were only covered by unit tests in this run.
4. **WIP in the tree.** The Markdown viewer and the terminal/layout edits are unreleased. They need their own pass, including hostile-Markdown rendering and the format fix.

## 8. Release verdict

**GO WITH RISKS** for 0.1.2 as committed.

- Every automated gate passes on the committed code, the security posture is unusually solid, and no critical defects were found.
- BUG-01 is major but has a workaround: stop terminals before removing a project, or quit the app. It is not a regression of a core flow.
- Recommended before the **next** release:
  - Fix BUG-01 and add an E2E test for it.
  - Run the manual upgrade/auto-update check on a clean VM.
  - Fix formatting in the Markdown WIP (BUG-02) and give the viewer a hostile-input pass before it ships.

## 9. Reproducing this run

```bash
pnpm format:check; pnpm lint; pnpm typecheck; pnpm test   # check each exit code (pnpm -s hides failures)
pnpm build && pnpm e2e
```
The exploratory and triage suites were temporary Playwright specs under `apps/desktop/e2e/`, driving the built app with `launchApp()` from `e2e/app.ts`. They were removed after the run. The checks are listed in §6 so they can be rebuilt as permanent tests. The best candidates are BUG-01, SEC-02…07, SEC-11…18 and DATA-01.
